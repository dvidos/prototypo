# transactional language

What if the language, instead of describing a system, could describe changes to a system?

In most cases, engineering is about changes, not about state.

Think of a language that one can write a program that makes changes to a system. For example, actions could be:

* Create, rename, remove an entity, an endpoint, a service etc.
* Add, rename, remove an attribute to/in/from an entity, request, response, event etc
